# SOP / 业务文档切块规则

生成业务 Skill 前，先判断是否要把业务文档切块，以及怎么切。**不以固定字数截断，以业务语义为边界。**

## 判断是否切块

出现任一情况即考虑切块：

- 文档超过可可靠处理的上下文规模。
- 有明确章节、模块或角色边界。
- 规则存在跨章节依赖（切块后需补关联索引）。
- 有大表格、字段字典、评分公式或大量平台规则。
- 数据源规则版本差异大或更新频繁。

## 切块边界（按业务语义）

常见切块单位：

```
采集规则         平台字段映射
SKU 属性标准     聚类与渗透率规则
趋势计算规则     机会评分规则
产品结构表字段   报告输出模板
异常处理规则
```

## 每块必须保留的元信息

- 来源（原文档哪个章节）
- 章节路径
- 适用范围（哪个模块）
- 关联模块（依赖/被依赖）
- 版本

## 切块后的关联方式

- 每个块落成一个 `references/*.md`。
- `SKILL.md` 用「何时读哪个文件」做路由，不复制内容。
- 跨块依赖在文件顶部用 `关联: [[other-file]]` 标注。
