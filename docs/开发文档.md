
› Agent 自动流程（SOP）                                                                                                                                                            
  1. 采集 Agent 7×24 爬取亚马逊 / 1688 / 海外社媒的竞品 SKU、价格、销量、评价、                                                                                                    
  上架时间。                                                                                                                                                                       
  2. 聚类 Agent 对全市场 SKU 做「属性组合渗透率」分析，自动标记渗透率为 0% 的蓝                                                                                                    
  海组合。                                                                                                                                                                         
  3. 趋势 Agent 监控价格带迁移、功能词热度、品类热度变化，输出《趋势预警》。
  4. 机会 Agent 汇总成《周度选品机会清单》，每个机会标注：创新分、竞争度、可解                                                                                                     
  释场景、契合现有货号。                                                                                                                                                           
  5. 回流：选品结果 → 更新产品结构表 → 触发内容生产 Agent 进入下一环节。   我现在有这个sop，我需要根据我之前的想法进行设计，首先需要去爬取相关数据，其次根据每个模块设计一个       
  skill，然后对其进行使用，我这个skill的优点就是减少了，开发者开发完之后给用户使用之后出现了问题，然后用户反馈问题，开发者再进行重新优化。而是用户在使用这个skill中出现了问题，ai  
  自动保存问题，然后在用户提出修复问题的时候再进行处理，通过这样可以先让用户将所有流程测试完成之后再进行优化，也提高了skill优化的效率，先给我一个方案，不需要执行任何其他操作      
                                                                                                                                                                                   
                                                                                                                                                                                   
• 方案应分成两层：一层是“选品业务 Agent 流水线”，另一层是“Skill 生成与持续优化工厂”。后者负责从你的 SOP 生成、测试和迭代前者所需的各个 Skill。                                     
                                                                                                                                                                                   
  ## 目标架构                                                                                                                                                                      
                                                                                                                                                                                   
  业务 SOP                                                                                                                                                                         
    ↓                                                                                                                                                                              
  Skill 工厂分析 SOP、数据源、模块依赖和风险                                                                                                                                       
    ↓                                                                                                                                                                              
  生成模块化 Skill                                                                                                                                                                 
    ↓                                                                                                                                                                              
  运行选品流水线                                                                                                                                                                   
    ↓                                                                                                                                                                              
  用户试用与验收                                                                                                                                                                   
    ↓                                                                                                                                                                              
  AI 自动记录问题 + AI 自检发现问题                                                                                                                                                
    ↓                                                                                                                                                                              
  问题暂存，不即时改动                                                                                                                                                             
    ↓                                                                                                                                                                              
  用户说“修复问题 / 处理反馈 / 优化 Skill”                                                                                                                                         
    ↓                                                                                                                                                                              
  批量定位根因、修改、回归测试、发布新版本                                                                                                                                         
                                                                                                                                                                                   
  ## 一、按 SOP 拆分的业务 Skill                                                                                                                                                   
                                                                                                                                                                                   
  建议不把所有流程写进一个大 Skill，而是生成一个编排 Skill 加五个领域 Skill。                                                                                                      
                                                                                                                                                                                   
  product-selection-orchestrator/   # 总调度与状态传递                                                                                                                             
  competitor-data-collector/        # 采集 Agent                                                                                                                                   
  sku-attribute-clustering/         # 聚类 Agent                                                                                                                                   
  market-trend-monitor/             # 趋势 Agent                                                                                                                                   
  product-opportunity-ranking/      # 机会 Agent                                                                                                                                   
  product-structure-feedback/       # 回流 Agent                                                                                                                                   
                                                                                                                                                                                   
  各模块职责如下：                                                                                                                                                                 
                                                                                                                                                                                   
   Skill                             主要输入                        主要输出                        依赖                                                                          
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  ━━━━━━━━━━━━━━━━━━━━━━                                                         
   competitor-data-collector         平台、类目、关键词、时间范围    标准化竞品 SKU 数据集           数据源/API/爬虫授权                                                           
  ────────────────────────────────  ──────────────────────────────  ──────────────────────────────  ──────────────────────                                                         
   sku-attribute-clustering          SKU 数据、属性定义              属性组合、渗透率、蓝海组合      采集数据、属性字典                                                            
  ────────────────────────────────  ──────────────────────────────  ──────────────────────────────  ──────────────────────                                                         
   market-trend-monitor              历史数据、时间窗口              《趋势预警》                    SKU 数据、关键词热度                                                          
  ────────────────────────────────  ──────────────────────────────  ──────────────────────────────  ──────────────────────                                                         
   product-opportunity-ranking       聚类结果、趋势预警、现有货号    《周度选品机会清单》            前两模块、产品结构表                                                          
  ────────────────────────────────  ──────────────────────────────  ──────────────────────────────  ──────────────────────                                                         
   product-structure-feedback        已确认的选品结果                更新后的产品结构表、内容任务    机会清单、产品结构表                                                          
  ────────────────────────────────  ──────────────────────────────  ──────────────────────────────  ──────────────────────
   product-selection-orchestrator    执行周期、任务范围              全流程状态、最终汇总            全部子 Skill                                                                  
                                                                                                                                                                                   
  其中总调度 Skill 不直接重复各模块业务规则，只负责：                                                                                                                              
                                                                                                                                                                                   
  - 检查上游结果是否完整。                                                                                                                                                         
  - 按顺序调用或提示使用对应模块。                                                                                                                                                 
  - 传递数据集版本、执行时间、类目和任务 ID。                                                                                                                                      
  - 阻止不完整数据直接进入后续决策。                                                                                                                                               
  - 汇总每周执行结果和失败项。                                                                                                                                                     
                                                                                                                                                                                   
  ## 二、Skill 工厂自身的工作流程                                                                                                                                                  
                                                                                                                                                                                   
  你要创建的核心 Skill 可以叫：                                                                                                                                                    
                                                                                                                                                                                   
  business-skill-factory                                                                                                                                                           
                                                                                                                                                                                   
  它根据业务文档/SOP 生成上述各业务 Skill。                                                                                                                                        
                                                                                                                                                                                   
  ### 1. 收集材料                                                                                                                                                                  
                                                                                                                                                                                   
  启动时索取：                                                                                                                                                                     
                                                                                                                                                                                   
  - 业务 SOP。                                                                                                                                                                     
  - 数据源说明，例如亚马逊、1688、海外社媒的访问方式、字段和权限。                                                                                                                 
  - 产品结构表的字段定义与存储位置。                                                                                                                                               
  - 目标类目、市场、国家站点。                                                                                                                                                     
  - 评分规则，例如创新分、竞争度、契合度的计算依据。                                                                                                                               
  - 输出模板，例如《趋势预警》《周度选品机会清单》。                                                                                                                               
  - 现有代码、数据库、接口或已有爬虫。                                                                                                                                             
  - 已知限制，例如不能抓取的数据、频率限制、人工审核节点。                                                                                                                         
                                                                                                                                                                                   
  ### 2. 分析是否需要切块                                                                                                                                                          
                                                                                                                                                                                   
  对 SOP、业务文档和规则文档分别判断：                                                                                                                                             
                                                                                                                                                                                   
  - 文档是否超过可可靠处理的上下文规模。                                                                                                                                           
  - 是否有明确章节、模块或角色边界。                                                                                                                                               
  - 规则是否存在跨章节依赖。                                                                                                                                                       
  - 是否有大表格、字段字典、评分公式或大量平台规则。                                                                                                                               
  - 是否存在版本差异或更新频繁的数据源规则。                                                                                                                                       
                                                                                                                                                                                   
  切块时以业务语义为边界，例如：                                                                                                                                                   
                                                                                                                                                                                   
  采集规则                                                                                                                                                                         
  平台字段映射                                                                                                                                                                     
  SKU 属性标准                                                                                                                                                                     
  聚类与渗透率规则                                                                                                                                                                 
  趋势计算规则                                                                                                                                                                     
  机会评分规则                                                                                                                                                                     
  产品结构表字段                                                                                                                                                                   
  报告输出模板                                                                                                                                                                     
  异常处理规则                                                                                                                                                                     
                                                                                                                                                                                   
  不应按固定字数截断。每个块都保留来源、章节路径、适用范围、关联模块和版本。                                                                                                       

  ### 3. 生成的 Skill 结构                                                                                                                                                         
                                                                                                                                                                                   
  每个业务 Skill 采用相同结构：                                                                                                                                                    
                                                                                                                                                                                   
  .agents/skills/<skill-name>/                                                                                                                                                     
  ├── SKILL.md                 # 仅做触发条件、路由、输入输出和流程约束                                                                                                            
  ├── references/                                                                                                                                                                  
  │   ├── data-schema.md                                                                                                                                                           
  │   ├── business-rules.md                                                                                                                                                        
  │   ├── scoring-rules.md                                                                                                                                                         
  │   ├── source-map.md
  │   ├── exceptions.md                                                                                                                                                            
  │   └── report-template.md                                                                                                                                                       
  ├── scripts/                 # 确定性数据处理、校验、报告生成                                                                                                                    
  ├── evals/                                                                                                                                                                       
  │   └── evals.json                                                                                                                                                               
  └── feedback/                                                                                                                                                                    
      ├── pending.jsonl                                                                                                                                                            
      ├── resolved.jsonl                                                                                                                                                           
      ├── self-review.jsonl                                                                                                                                                        
      └── changelog.md                                                                                                                                                             
                                                                                                                                                                                   
  SKILL.md 只说明何时读取哪个参考文件。例如，采集平台字段时加载 data-schema.md，生成机会清单时加载 scoring-rules.md 和 report-template.md，而不是一次性加载全部业务资料。          
                                                                                                                                                                                   
  ## 三、业务执行中的自检机制                                                                                                                                                      
                                                                                                                                                                                   
  这是你补充的关键要求。AI 不应只等用户反馈，也要在每次任务完成后自检。                                                                                                            
                                                                                                                                                                                   
  每个 Skill 执行后自动产出两类结果：                                                                                                                                              
                                                                                                                                                                                   
  业务输出                                                                                                                                                                         
  自检报告                                                                                                                                                                         
                                                                                                                                                                                   
  自检重点包括：                                                                                                                                                                   
                                                                                                                                                                                   
  - 输入数据是否缺失、过期、重复或字段不一致。                                                                                                                                     
  - 采集数量是否相对历史异常下降。                                                                                                                                                 
  - 价格、销量、评分是否存在明显异常值。                                                                                                                                           
  - 聚类属性是否大量为空、属性组合是否不合理。                                                                                                                                     
  - “渗透率 0%”是否只是因样本缺失造成的假蓝海。                                                                                                                                    
  - 趋势是否有足够历史窗口支撑。                                                                                                                                                   
  - 创新分、竞争度、契合度是否可追溯到输入数据。                                                                                                                                   
  - 产品结构表更新是否成功，字段是否符合 schema。                                                                                                                                  
  - 输出结论是否包含未经数据支持的推断。                                                                                                                                           
  - Skill 是否因为业务规则缺失而被迫猜测。                                                                                                                                         
                                                                                                                                                                                   
  AI 自检发现的问题也写入问题库，但标注来源：                                                                                                                                      
                                                                                                                                                                                   
  user_feedback       # 用户发现                                                                                                                                                   
  self_review         # AI 自检发现                                                                                                                                                
  data_validation     # 数据质量校验发现                                                                                                                                           
  test_failure        # 测试发现                                                                                                                                                   
                                                                                                                                                                                   
  这样用户后续要求修复时，既能处理用户反馈，也能处理 AI 在运行期间积累的隐患。                                                                                                     
                                                                                                                                                                                   
  ## 四、延迟修复机制                                                                                                                                                              
                                                                                                                                                                                   
  默认行为是“记录，不即时修改”。                                                                                                                                                   
                                                                                                                                                                                   
  用户提出：                                                                                                                                                                       
                                                                                                                                                                                   
  趋势报告中价格带错了                                                                                                                                                             
  这个蓝海组合不可信                                                                                                                                                               
  1688 的字段映射有问题                                                                                                                                                            
  机会清单没有考虑现有货号                                                                                                                                                         
                                                                                                                                                                                   
  AI 应执行：                                                                                                                                                                      

  1. 保存用户原始输入、当时 Skill 版本、输入数据版本和实际输出。                                                                                                                   
  2. 记录涉及的模块、严重程度和可能根因。                                                                                                                                          
  3. 给用户简短确认：问题已记录，当前不改动正式 Skill。                                                                                                                            
  4. 继续后续流程测试。                                                                                                                                                            
                                                                                                                                                                                   
  只有用户明确提出以下意图才启动优化：                                                                                                                                             
                                                                                                                                                                                   
  修复问题                                                                                                                                                                         
  处理反馈                                                                                                                                                                         
  统一优化                                                                                                                                                                         
  根据测试结果更新                                                                                                                                                                 
  修复待处理问题
  发布新版本                                                                                                                                                                       
                                                                                                                                                                                   
  之后 AI 才批量执行：                                                                                                                                                             
                                                                                                                                                                                   
  汇总问题                                                                                                                                                                         
    ↓                                                                                                                                                                              
  去重和分类                                                                                                                                                                       
    ↓                                                                                                                                                                              
  识别根因                                                                                                                                                                         
    ↓                                                                                                                                                                              
  判断修改的是数据、规则、提示词、脚本还是测试                                                                                                                                     
    ↓                                                                                                                                                                              
  生成修改计划                                                                                                                                                                     
    ↓                                                                                                                                                                              
  修改 Skill                                                                                                                                                                       
    ↓                                                                                                                                                                              
  补充回归测试                                                                                                                                                                     
    ↓                                                                                                                                                                              
  运行测试                                                                                                                                                                         
    ↓                                                                                                                                                                              
  输出版本变更报告                                                                                                                                                                 
                                                                                                                                                                                   
  ## 五、问题不能直接变成规则                                                                                                                                                      
                                                                                                                                                                                   
  这是避免 Skill 越改越乱的核心控制。                                                                                                                                              
                                                                                                                                                                                   
  每一条问题都要先归类：                                                                                                                                                           
                                                                                                                                                                                   
   问题类型              处理方式                                                                                                                                                  
  ━━━━━━━━━━━━━━━━━━━━  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━                                                                                                                       
   数据缺失或脏数据      修复采集、清洗或数据校验                                                                                                                                  
  ────────────────────  ────────────────────────────────────                                                                                                                       
   原 SOP 规则遗漏       补充对应参考资料或 Skill 路由                                                                                                                             
  ────────────────────  ────────────────────────────────────                                                                                                                       
   Skill 理解错误        精准修改指令或决策规则                                                                                                                                    
  ────────────────────  ────────────────────────────────────                                                                                                                       
   切块导致上下文丢失    调整文档块边界和关联索引                                                                                                                                  
  ────────────────────  ────────────────────────────────────                                                                                                                       
   测试覆盖不足          新增回归测试，不一定改业务规则                                                                                                                            
  ────────────────────  ────────────────────────────────────                                                                                                                       
   原文档未定义          标记待业务确认，不能擅自编造                                                                                                                              
  ────────────────────  ────────────────────────────────────                                                                                                                       
   用户新增要求          作为需求变更，单独确认后纳入                                                                                                                              
  ────────────────────  ────────────────────────────────────                                                                                                                       
   模型推断不可靠        增加证据要求、置信度和禁止推断规则                                                                                                                        
                                                                                                                                                                                   
  ## 六、测试体系                                                                                                                                                                  
                                                                                                                                                                                   
  每个模块至少需要三类测试：                                                                                                                                                       
                                                                                                                                                                                   
  - 结构测试：Skill 文件、路由、参考资料、脚本和索引是否完整。                                                                                                                     
  - 数据测试：字段映射、去重、异常值、时间窗口、评分公式是否正确。                                                                                                                 
  - 业务场景测试：真实选品场景、缺失数据、冲突数据、低样本蓝海、无趋势变化、无法匹配现有货号等。                                                                                   
                                                                                                                                                                                   
  全流程还要有端到端测试：                                                                                                                                                         
                                                                                                                                                                                   
  模拟采集数据                                                                                                                                                                     
    → 属性组合渗透率计算                                                                                                                                                           
    → 趋势预警                                                                                                                                                                     
    → 周度机会清单                                                                                                                                                                 
    → 产品结构表更新                                                                                                                                                               
    → 内容生产任务触发                                                                                                                                                             
                                                                                                                                                                                   
  每一个测试应验证可观察行为，例如“样本量不足时不允许将 0% 渗透率直接判定为蓝海”，而不是只检查报告文字是否相同。                                                                   
                                                                                                                                                                                   
  ## 七、版本和可追溯性                                                                                                                                                            
                                                                                                                                                                                   
  每次生成或优化后记录：                                                                                                                                                           

  Skill 版本                                                                                                                                                                       
  业务文档版本                                                                                                                                                                     
  数据 schema 版本                                                                                                                                                                 
  关联反馈编号                                                                                                                                                                     
  关联自检编号                                                                                                                                                                     
  修改文件                                                                                                                                                                         
  变更原因                                                                                                                                                                         
  新增测试                                                                                                                                                                         
  测试结果                                                                                                                                                                         
  待业务确认项                                                                                                                                                                     
                                                                                                                                                                                   
  这会让你能够回答：                                                                                                                                                               
                                                                                                                                                                                   
  - 某一条选品建议使用了哪一版规则？                                                                                                                                               
  - 某个问题为什么被修改？                                                                                                                                                         
  - 某次优化是否引入了回归问题？                                                                                                                                                   
  - 当前哪些问题仍等待用户决定？                                                                                                                                                   
                                                                                                                                                                                   
  这套方案保留了你最初的所有要求：先拿业务文档、判断是否切块、按模块生成 Skill、测试、记录用户反馈、延迟批量修复；并新增了 AI 主动自检、问题分类、可追溯版本和端到端回归测试。     
                                                                                                                                                                                   
                                                                                                                                                                                   
› 如果要你写测试用例，你会怎么执行，并且并不是所有问题ai都能解决，出现了不能解决的情况下，需要记录并且提交给开发者                                                                 
                                                                                                                                                                                   
                                                                                                                                                                                   
• 我会把测试设计成“模块测试 + 端到端测试 + 试用反馈测试”，并把无法自动解决的问题进入开发者待办队列。                                                                               
                                                                                                                                                                                   
  测试执行流程：                                                                                                                                                                   
                                                                                                                                                                                   
  生成或更新 Skill                                                                                                                                                                 
    ↓                                                                                                                                                                              
  自动生成测试用例初稿                                                                                                                                                             
    ↓                                                                                                                                                                              
  执行模块测试                                                                                                                                                                     
    ↓                                                                                                                                                                              
  执行端到端测试                                                                                                                                                                   
    ↓                                                                                                                                                                              
  AI 自检并分类失败原因                                                                                                                                                            
    ↓                                                                                                                                                                              
  能自动修复的：暂存到待修复列表                                                                                                                                                   
  不能自动修复的：创建开发者工单                                                                                                                                                   
    ↓                                                                                                                                                                              
  用户说“修复问题”后，批量处理可自动修复项                                                                                                                                         
                                                                                                                                                                                   
  每个模块的测试用例应包含正常、边界、异常和数据质量场景。例如：                                                                                                                   
                                                                                                                                                                                   
   模块    测试用例                        预期行为                                                                                                                                
  ━━━━━━  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━                                                                                                       
   采集    平台正常返回 SKU 数据           标准化字段并保存数据版本                                                                                                                
  ──────  ──────────────────────────────  ──────────────────────────────────                                                                                                       
   采集    价格为空、销量格式异常          标记脏数据，不进入评分                                                                                                                  
  ──────  ──────────────────────────────  ──────────────────────────────────                                                                                                       
   采集    反爬、登录失效、页面结构变化    停止重试，记录并转开发者                                                                                                                
  ──────  ──────────────────────────────  ──────────────────────────────────                                                                                                       
   聚类    属性完整的 SKU 数据             输出属性组合与渗透率                                                                                                                    
  ──────  ──────────────────────────────  ──────────────────────────────────                                                                                                       
   聚类    样本量过少且渗透率为 0%         标记“数据不足”，不能直接称为蓝海                                                                                                        
  ──────  ──────────────────────────────  ──────────────────────────────────
   趋势    过去数周价格带上移              输出价格带迁移预警及证据                                                                                                                
  ──────  ──────────────────────────────  ──────────────────────────────────                                                                                                       
   趋势    时间窗口不足                    提示无法形成可靠趋势结论                                                                                                                
  ──────  ──────────────────────────────  ──────────────────────────────────                                                                                                       
   机会    有趋势、低竞争、现有货号适配    输出机会及评分证据                                                                                                                      
  ──────  ──────────────────────────────  ──────────────────────────────────                                                                                                       
   回流    产品结构表字段完整              更新结构表并生成内容任务                                                                                                                
  ──────  ──────────────────────────────  ──────────────────────────────────                                                                                                       
   回流    产品结构表 schema 不兼容        不写入，转开发者或业务确认                                                                                                              
                                                                                                                                                                                   
  端到端测试使用一套固定的模拟数据：                                                                                                                                               
                                                                                                                                                                                   
  模拟竞品数据                                                                                                                                                                     
    → 采集标准化                                                                                                                                                                   
    → 属性聚类                                                                                                                                                                     
    → 蓝海候选识别                                                                                                                                                                 
    → 趋势预警                                                                                                                                                                     
    → 周度机会清单                                                                                                                                                                 
    → 产品结构表更新                                                                                                                                                               
    → 内容生产任务触发                                                                                                                                                             
                                                                                                                                                                                   
  关键断言不是“报告文字完全一致”，而是验证业务行为，例如：                                                                                                                         
                                                                                                                                                                                   
  - 没有采集数据时，不能生成机会清单。                                                                                                                                             
  - 样本不足时，不能将 0% 渗透率判定为蓝海。                                                                                                                                       
  - 趋势结论必须有时间窗口和原始数据支持。                                                                                                                                         
  - 创新分、竞争度、契合度必须可追溯。                                                                                                                                             
  - 产品结构表校验失败时，不能触发内容生产。                                                                                                                                       
                                                                                                                                                                                   
  无法解决的问题应有独立状态，而不是混在普通反馈中。建议状态如下：                                                                                                                 
                                                                                                                                                                                   
  pending          已记录，待统一处理                                                                                                                                              
  auto-fixable     AI 判断可以通过规则、文档、测试或脚本修改解决                                                                                                                   
  needs-business   需要业务确认，例如评分口径不清                                                                                                                                  
  needs-developer  需要开发者介入，例如爬虫失效、API 故障、数据库问题                                                                                                              
  resolved         已修复并通过回归测试                                                                                                                                            
                                                                                                                                                                                   
  提交给开发者的工单至少包含：                                                                                                                                                     
                                                                                                                                                                                   
  {                                                                                                                                                                                
    "issue_id": "DEV-20260910-001",                                                                                                                                                
    "source": "self_review | user_feedback | test_failure",                                                                                                                        
    "module": "competitor-data-collector",                                                                                                                                         
    "skill_version": "0.3.0",                                                                                                                                                      
    "severity": "high",                                                                                                                                                            
    "summary": "亚马逊页面字段结构变化，价格字段无法解析",                                                                                                                         
    "reproduction_input": "站点、类目、SKU 或 URL",                                                                                                                                
    "expected_behavior": "提取标准化价格字段",                                                                                                                                     
    "actual_behavior": "价格为空，数据校验失败",                                                                                                                                   
    "evidence": "原始响应、日志、截图或错误信息路径",                                                                                                                              
    "ai_diagnosis": "疑似页面 DOM 或反爬策略变更",                                                                                                                                 
    "attempted_actions": ["重试", "备用解析规则", "字段校验"],                                                                                                                     
    "recommended_owner": "crawler-developer",                                                                                                                                      
    "status": "needs-developer"                                                                                                                                                    
  }                                                                                                                                                                                
                                                                                                                                                                                   
  AI 应只在有明确、低风险修复依据时修改 Skill。例如补充遗漏的 SOP 规则、修正参考文件路由、增加输入校验、补齐测试用例。                                                             
                                                                                                                                                                                   
  以下情况应停止自动修改并提交开发者或业务方：                                                                                                                                     
                                                                                                                                                                                   
  - 爬虫、API、账号、网络、反爬或页面结构问题。                                                                                                                                    
  - 数据库、权限、部署、定时任务失败。                                                                                                                                             
  - 需要修改真实代码、基础设施或第三方服务配置。
  - 业务规则、评分口径、字段含义未定义或互相冲突。                                                                                                                                 
  - 无法证明某个“蓝海机会”是数据问题还是市场事实。                                                                                                                                 
  - 多次修复仍复现，或修改可能影响多个模块。                                                                                                                                       
                                                                                                                                                                                   
  这样，用户可以完整跑完流程再说“修复问题”；AI 会批量处理可解决项，同时把真正需要开发者或业务确认的问题整理成可复现、可分配的任务。 


                                                                                                                                                                                   
› 可追溯版本如何呈现呢？像github  仓库一样嘛？还是怎么设计                                                                                                                         
                                                                                                                                                                                   
                                                                                                                                                                                   
• 建议采用“Git 仓库 + 结构化运行记录”的组合，不建议只靠 Git，也不建议完全脱离 Git。                                                                                                
                                                                                                                                                                                   
  Git 适合管理“可修改、可回滚、需要评审”的内容：                                                                                                                                   
                                                                                                                                                                                   
  Skill 指令                                                                                                                                                                       
  参考资料                                                                                                                                                                         
  脚本                                                                                                                                                                             
  测试用例                                                                                                                                                                         
  数据 schema                                                                                                                                                                      
  评分规则                                                                                                                                                                         
  报告模板                                                                                                                                                                         
                                                                                                                                                                                   
  而用户反馈、运行日志、采集数据版本、任务执行状态更适合保存在结构化问题库或数据库中，再通过版本号关联到 Git Commit。                                                              
                                                                                                                                                                                   
  整体关系可以这样设计：                                                                                                                                                           
                                                                                                                                                                                   
  Git Commit                                                                                                                                                                       
    ├── Skill 版本：v0.3.0                                                                                                                                                         
    ├── 修改的业务规则/脚本/测试                                                                                                                                                   
    └── release-manifest.json                                                                                                                                                      
            ├── 来源 SOP 版本                                                                                                                                                      
            ├── 已处理反馈 ID                                                                                                                                                      
            ├── 未处理问题 ID                                                                                                                                                      
            ├── 测试结果                                                                                                                                                           
            └── 数据 schema 版本
                                                                                                                                                                                   
  Issue / 反馈库                                                                                                                                                                   
    ├── 用户反馈                                                                                                                                                                   
    ├── AI 自检问题                                                                                                                                                                
    ├── 测试失败                                                                                                                                                                   
    ├── 业务待确认项                                                                                                                                                               
    └── 开发者待处理项                                                                                                                                                             
                                                                                                                                                                                   
  推荐目录：                                                                                                                                                                       
                                                                                                                                                                                   
  product-selection-skills/                                                                                                                                                        
  ├── .agents/skills/                                                                                                                                                              
  │   ├── competitor-data-collector/

  │   └── product-structure-feedback/                                                                                                                                              
  ├── evals/                                                                                                                                                                       
  │   ├── fixtures/                 # 脱敏、固定的测试数据                                                                                                                         
  │   ├── cases/                                                                                                                                                                   
  │   └── reports/                                                                                                                                                                 
  ├── schemas/                                                                                                                                                                     
  │   ├── competitor-sku.schema.json                                                                                                                                               
  │   ├── product-structure.schema.json                                                                                                                                            
  │   └── opportunity.schema.json                                                                                                                                                  
  ├── releases/                                                                                                                                                                    
  │   └── v0.3.0/                                                                                                                                                                  
  │       ├── release-manifest.json                                                                                                                                                
  │       ├── test-report.md

    "schema_versions": {                                                                                                                                                           
      "competitor_sku": "v1.2",                                                                                                                                                    
      "opportunity": "v1.0"                                                                                                                                                        
    },                                                                                                                                                                             
    "resolved_issues": ["FB-021", "AI-008"],                                                                                                                                       
    "open_issues": ["DEV-014", "BIZ-007"],

    "approval_status": "approved"

  {                                                                                                                                                                                
    "run_id": "RUN-20260910-001",                                                                                                                                                  
    "skill_release": "v0.3.0",

    "input_data_version": "competitor-snapshot-2026w37",

      "trend-alert-2026w37",                                                                                                                                                       
      "opportunity-list-2026w37"                                                                                                                                                   
    ],                                                                                                                                                                             
    "self_review_issue_ids": ["AI-031"],                                                                                                                                           
    "status": "completed_with_warnings"

  这能追溯到：
                                                                                                                                                                                   
  - 某个机会清单由哪一版 Skill 生成。                                                                                                                                              
  - 当时使用了哪批竞品数据。                                                                                                                                                       
  - 创新分和竞争度依据的是哪版规则。                                                                                                                                               
  - 当时有哪些已知问题未修复。                                                                                                                                                     
  - 后续哪个反馈促成了规则修改。                                                                                                                                                   
  - 某次修改是否通过测试并由谁批准。                                                                                                                                               
                                                                                                                                                                                   
  工作流上可类比 GitHub，但不一定需要一开始接入完整 GitHub Issue 或 Pull Request 流程：                                                                                            

  用户反馈 / AI 自检                                                                                                                                                               
    → issues/pending                                                                                                                                                               
    → 用户要求“修复问题”                                                                                                                                                           
    → 创建优化分支                                                                                                                                                                 
    → 修改 Skill、规则、脚本和测试                                                                                                                                                 
    → 将问题标记 resolved / needs-developer / needs-business

  第一阶段可以使用本地 Git 仓库、JSONL 问题文件和 Markdown 测试报告，成本最低。后续多人协作时，再将 needs-developer 自动同步到 GitHub Issues、Jira、禅道或企业内部工单系统。这样既 
  保留 Git 的版本回滚和差异对比能力，也不会把高频运行日志和用户反馈变成大量无意义的提交。
